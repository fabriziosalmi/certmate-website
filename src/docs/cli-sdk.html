CLI and Python SDK

How to install and configure the certmate command and the certmate-sdk Python package, what each command and method calls, and how issuance jobs are awaited.

Two Packages

CertMate has two first-party Python clients for its REST API. Both live in the clients/ directory of the CertMate repository and are published to PyPI.

  • certmate-sdk 0.1.5: the certmate Python package, with Client, two models and a set of exceptions. Its only runtime dependency is httpx>=0.24.
  • certmate-cli 0.1.5: the certmate command. It is built on the SDK and depends on certmate-sdk>=0.1.5, typer>=0.9 and rich>=13.

Both require Python 3.9 or later. Neither package pulls in certbot, DNS plugins or cloud SDKs.

pip install certmate-cli    # installs certmate-sdk as well
pip install certmate-sdk    # the library alone

From a checkout of the CertMate repository, install the in-repo copies in editable mode:

pip install -e clients/certmate-sdk -e clients/certmate-cli

The clients work against any CertMate v2.x server. Two features need server v2.21.1 or later: the renewed/not-due outcome of cert renew, and dns test or cert create --dry-run without explicit credentials, which relies on the server using the provider's stored account credentials when the config is empty.

Configuration

The CLI and the SDK read the same two environment variables:

VariableCLI flagMeaning
CERTMATE_URL--urlBase URL of the CertMate server. Default http://localhost:8000.
CERTMATE_TOKEN--tokenAPI token, sent as Authorization: Bearer <token>. Omit it on a fresh instance still in setup mode.
 
export CERTMATE_URL=https://certmate.example.com
export CERTMATE_TOKEN=...
certmate health

Use CERTMATE_TOKEN rather than --token: command-line arguments are visible to other local processes through ps and are saved in shell history. --token still works, and when it is given on the command line with stderr attached to a terminal the CLI prints a warning. Scripts and pipelines get no warning.

The global options go before the command group, for example certmate --url https://certmate.example.com cert ls. certmate --version (or -V) prints the certmate-cli version and exits without contacting a server.

CLI Commands

Each command below calls one SDK method, which calls one API endpoint. The token's role must allow the endpoint; see Security for roles and scoped API keys.

Options:

  • cert create: --dns PROVIDER, --ca PROVIDER, --san a.example.com,b.example.com (empty entries are dropped), --wait/--no-wait (default --wait), --dry-run.
  • cert renew: --force renews even when the certificate is not due.
  • cert reissue: --san, a comma-separated list sent as san_domains.
  • cert rm: --yes or -y skips the confirmation.
  • cert download: --file/-f (cert, chain, fullchain, privkey, combined or pfx; default fullchain), --output/-o (default the file's usual name in the current directory; - writes to stdout), --key-format pkcs1|pkcs8 (only with --file privkey), --bundle zip|json (the whole certificate instead of one file).

In cert ls and cert info a certificate with less than a day left is shown as <1 or "less than a day", not 0, and an expired one as expired. The CLI takes this from the server's expired and seconds_left fields; against a server that does not send them it shows ? for the ambiguous last day.

--dry-run

cert create DOMAIN --dry-run issues nothing. It checks locally that the domain and every SAN look like hostnames (a leading *. is allowed), and, when --dns is given, preflights that provider with POST /api/web/certificates/test-provider and an empty config, so the server uses the provider's stored credentials. Without --dns the provider check is skipped. Any problem is listed and the command exits 1.

certmate cert create app.example.com --dns cloudflare --dry-run

Pulling files onto a host

cert download lets a target server fetch what it deploys, instead of CertMate pushing to it. Give each host an API key scoped to its own domain and run the pull on a timer: the host needs no inbound access and CertMate holds no credentials for it.

certmate cert download app.example.com --file fullchain -o /etc/ssl/certs/app.pem
certmate cert download app.example.com --file privkey   -o /etc/ssl/private/app.key

A new file is created with mode 0600, set when the file is opened rather than afterwards. A file that already exists keeps its mode, and the CLI prints the mode it actually has. cert, chain and fullchain are readable with a viewer key; privkey, combined and pfx need operator. --key-format pkcs1 returns the BEGIN RSA PRIVATE KEY form for software that rejects certbot's PKCS#8. Options are checked before any request is sent.

Exit codes

  • 0: the command succeeded. --version also exits 0.
  • 1: any SDK error (the server was unreachable, the API returned an error, a job failed or timed out), with the message printed to stderr as error: .... Also a failed --dry-run, a failed dns test, an audit chain that is not intact, a deploy run the server reports as not ok, and an invalid cert download option.

Jobs and --wait

Issuance is asynchronous. The SDK sends "async": true to POST /api/certificates/create; the server accepts the request and returns a job ID.

  • With --wait (the CLI default) the CLI polls GET /api/certificates/jobs/JOB_ID every 2 seconds, shows the job status in a spinner, and prints issued when the job reaches a success state. A failed job exits 1 with the job's error. After 600 seconds without a terminal state it exits 1 with a timeout.
  • With --no-wait it prints accepted and the job ID. Check it later with certmate cert job JOB_ID.

A job is terminal when its status is succeeded, success, completed or done, or failed or error. While polling, a single network failure does not stop the wait; three consecutive ones do. If the server has already dropped a finished job from its job table, the SDK checks whether the certificate now exists and, if it does, treats the job as succeeded. If the server returns no job ID, the call is treated as having completed synchronously.

Renewal is a single request, not a job. The SDK gives it a 600-second timeout because a DNS-01 renewal waits for propagation.

Python SDK

from certmate import Client, CertMateError, JobFailed

with Client("https://certmate.example.com", token="...") as c:
    try:
        job = c.create_certificate("app.example.com",
                                   dns_provider="cloudflare", wait=True)
        print(job.job_id, job.status)
    except JobFailed as e:
        print("issuance failed:", e, e.job.error)

    for cert in c.list_certificates():
        print(cert.domain, cert.days_until_expiry, cert.has_expired())

    print(c.audit_verify()["ok"])

Client

Client(base_url=None, token=None, *, timeout=30.0, verify=True). base_url and token fall back to CERTMATE_URL and CERTMATE_TOKEN, and the URL defaults to http://localhost:8000. verify is passed to httpx for TLS verification. Connection-level failures are retried up to 3 times. Use the client as a context manager, or call close().

force, enabled and check_revocation must be real booleans; anything else raises TypeError before a request is made. download_certificate_file raises ValueError for an unknown file name, an unknown key_format, or a key_format on a file other than privkey. audit_verify returns the result for a broken chain (HTTP 409) instead of raising, so inspect result["ok"]. probe does not raise for a host that refuses the connection or does not resolve; that is reported in status.

Models

Certificate has domain, expiry_date, days_until_expiry, expired, seconds_left, needs_renewal, ca_provider, dns_provider, auto_renew, san_domains, and raw, the full response dict. Fields the server does not send are None; unknown fields are ignored.

To ask whether a certificate has expired, call cert.has_expired() rather than testing days_until_expiry <= 0. days_until_expiry is whole days rounded down, so a certificate with 23 hours left reports 0. has_expired() returns the server's expired field when the server sends it (API contract 2.2 and later). Otherwise it returns True for a negative day count, False for a positive one, and None for zero or a missing value.

Job has job_id, operation, domain, status, error and raw, and the properties is_terminal, succeeded and failed.

Errors

Every SDK exception derives from CertMateError, so one except clause covers them all.

ExceptionRaised when
TransportErrorThe server could not be reached or the connection failed (DNS failure, refused connection, timeout, protocol error).
APIErrorThe API returned a non-2xx status. Carries status, code (CertMate's machine-readable code, such as DOMAIN_OUT_OF_SCOPE, when present) and payload.
AuthErrorSubclass of APIError for 401 and 403.
