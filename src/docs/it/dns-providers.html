Provider DNS supportati

CertMate supporta {{PROVIDER_COUNT}} provider DNS per la challenge DNS-01 di ACME. Ognuno di essi può avere più di un account.

Supporto multi-account: ogni provider di questa pagina supporta più account — per separare gli ambienti (prod/staging/dev), per deployment multi-regione e per limitare i permessi. Non c’è alcun limite per provider.

Esempi di configurazione

Configurazione di Cloudflare

  1. Vai su Cloudflare API Tokens
  2. Fai clic su "Create Token" → "Custom token"
  3. Imposta i permessi: Zone → DNS:Edit + Zone:Read
  4. Copia il token generato

Inserisci il token in Settings, DNS Providers, oppure impostalo nell'ambiente. Cloudflare è l'unico provider DNS letto dall'ambiente; la variabile imposta l'account Cloudflare predefinito.

# Environment variable
CLOUDFLARE_TOKEN=your_cloudflare_api_token_here

Configurazione di AWS Route53

  1. Crea un utente IAM con permessi Route53
  2. Associa la policy AmazonRoute53FullAccess o una policy personalizzata
{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Action": [
      "route53:ListHostedZones",
      "route53:GetChange",
      "route53:ChangeResourceRecordSets"
    ],
    "Resource": "*"
  }]
}

Inserisci le credenziali in Settings, DNS Providers, o tramite l'API. Le variabili AWS_* nel container non vengono lette. I campi dell'account:

{
  "access_key_id": "your_access_key_id",
  "secret_access_key": "your_secret_access_key",
  "region": "us-east-1"
}

Configurazione di Azure DNS

# Create Service Principal
az ad sp create-for-rbac --name "CertMate" \
  --role "DNS Zone Contributor" \
  --scopes "/subscriptions/{subscription-id}/resourceGroups/{resource-group}"

Inserisci il service principal in Settings, DNS Providers, o tramite l'API. Le variabili AZURE_* nel container non vengono lette. I campi dell'account:

{
  "subscription_id": "your_subscription_id",
  "resource_group": "your_resource_group_name",
  "tenant_id": "your_tenant_id",
  "client_id": "your_client_id",
  "client_secret": "your_client_secret"
}

🏢 Configurazione multi-account

Per separare ambienti, regioni o permessi, configura più di un account per ciascun provider DNS:

Dall'interfaccia web

  1. Vai in Settings → DNS Providers
  2. Seleziona il provider (ad es. Cloudflare)
  3. Fai clic su "Add Account"
  4. Inserisci i dati dell'account e le credenziali
  5. Salva la configurazione

Tramite l'API

# Add production account
curl -X POST "http://localhost:8000/api/dns/cloudflare/accounts" \
  -H "Authorization: Bearer your_token" \
  -H "Content-Type: application/json" \
  -d '{
    "account_id": "production",
    "config": {
      "name": "Production Environment",
      "description": "Main production account",
      "api_token": "prod_token_here"
    }
  }'

# Add staging account
curl -X POST "http://localhost:8000/api/dns/cloudflare/accounts" \
  -H "Authorization: Bearer your_token" \
  -H "Content-Type: application/json" \
  -d '{
    "account_id": "staging",
    "config": {
      "name": "Staging Environment",
      "description": "Development and testing",
      "api_token": "staging_token_here"
    }
  }'

Usare account specifici per i certificati

# Create certificate with specific account
curl -X POST "http://localhost:8000/api/certificates/create" \
  -H "Authorization: Bearer your_token" \
  -H "Content-Type: application/json" \
  -d '{
    "domain": "api.company.com",
    "dns_provider": "cloudflare",
    "account_id": "production"
  }'

Casi d'uso multi-account

  • Separazione degli ambienti: account diversi per produzione, staging e sviluppo
  • Gestione multi-regione: account separati per regioni geografiche diverse
  • Isolamento dei team: account per reparto con permessi su misura
  • Disaster recovery: account di riserva per scenari ad alta disponibilità
  • Limitazione dei permessi: account con i soli permessi minimi necessari, per sicurezza
