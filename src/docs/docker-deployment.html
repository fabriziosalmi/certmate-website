Docker Deployment

Image, Compose, environment, volumes, upgrades and health checks

Image and Tags

The image is published on Docker Hub as fabriziosalmi/certmate. Release builds are published for linux/amd64 and linux/arm64; Docker pulls the matching architecture automatically. linux/arm/v7 is not published, but the image can be built for it (see Building the Image below).

Tags:

  • latest: moved only by a v* release tag. Pushes to main publish :main, not :latest.
  • MAJOR, MAJOR.MINOR and MAJOR.MINOR.PATCH, plus vMAJOR.MINOR and vMAJOR.MINOR.PATCH.

For production, pin a version tag such as fabriziosalmi/certmate:2.19 so that a re-pull does not upgrade you unintentionally.

The container runs as the non-root user certmate (UID 1000) under tini, and serves the app with gunicorn using one worker and eight threads. Run one container per data volume: the renewal scheduler runs inside the web process, so a second replica would be a second scheduler placing duplicate ACME orders against the same certificate store.

Run with docker run

docker run -d --name certmate \
  --env-file .env \
  -p 127.0.0.1:8000:8000 \
  -v certmate_data:/app/data \
  -v certmate_certificates:/app/certificates \
  -v certmate_logs:/app/logs \
  -v certmate_backups:/app/backups \
  fabriziosalmi/certmate:latest

Keep the .env file on the host. .dockerignore excludes every .env file from the build context, so configuration is supplied at run time and never baked into the image.

The web UI is then at http://localhost:8000, and the API documentation at /docs/ and /redoc/.

Run with Docker Compose

The repository's docker-compose.yml builds the image from source; to use the published image instead, uncomment its image: line.

git clone https://github.com/fabriziosalmi/certmate.git
cd certmate
cp .env.example .env
# edit .env

# bind mounts: prepare the host directories once (see Volumes)
mkdir -p ./{certificates,data,logs,backups}
chgrp -R 0 ./{certificates,data,logs,backups}
chmod -R g+rwX ./{certificates,data,logs,backups}

docker compose up -d
docker compose ps
docker compose logs -f certmate

The compose service publishes 127.0.0.1:8000:8000, drops all Linux capabilities, restarts unless-stopped, limits the container to 512 MB of memory and one CPU, and rotates the json-file log at 10 MB, keeping three files.

To build with optional DNS plugins or storage backends, set EXTRA_REQUIREMENTS in .env to a space-separated list of requirements files, for example EXTRA_REQUIREMENTS=requirements-azure.txt requirements-storage-all.txt. It is a build argument, so it takes effect on the next build.

Environment Variables

These are read by the application. .env.example lists only variables that something reads, and a test fails the build if one does not.

  • API_BEARER_TOKEN: API authentication token, auto-generated if unset. Set it before a not-yet-onboarded instance is reachable from a network: until the first admin exists, an instance without it serves the setup bypass to anyone who can reach it. When it is set, the first-run screen asks you to paste it once to create the admin. The value is authoritative: if it differs from the stored token, the stored one is replaced at startup.
  • API_BEARER_TOKEN_FILE: path to a file holding the token; takes precedence over API_BEARER_TOKEN.
  • SECRET_KEY: Flask session key. If unset, or set to a placeholder such as change-me, CertMate generates one and persists it as /app/data/.secret_key so sessions survive restarts.
  • SECRET_KEY_FILE: path to a file holding the key; takes precedence over SECRET_KEY. If the file cannot be read or is empty, CertMate refuses to start.
  • CERTMATE_BACKUP_PASSPHRASE: see Backups below.
  • CLOUDFLARE_TOKEN: seeds the default Cloudflare DNS account.
  • LETSENCRYPT_EMAIL: ACME account email. It overrides the email saved in the web UI.
  • PORT: listen port inside the container, default 8000. If you change it, change the ports: mapping too.
  • GUNICORN_TIMEOUT: worker timeout in seconds, default 300. DNS-01 challenges on slow DNS services can take up to five minutes.
  • BEHIND_PROXY: see Reverse Proxy below.
  • SESSION_TIMEOUT_HOURS: login session lifetime, default 8.
  • CERTMATE_LOG_LEVEL (default INFO), CERTMATE_LOG_JSON (default true), CERTMATE_LOG_FILE: see Logs below.
  • CERTMATE_CERT_DIR: where issued certificates live, default /app/certificates. See Volumes below.

Variables that do nothing

  • DNS credentials other than Cloudflare's. Route53, Azure, Google Cloud DNS, PowerDNS and the rest are configured in the web UI (Settings, DNS Providers) or through the API. Setting AWS_ACCESS_KEY_ID or AZURE_CLIENT_ID in the container has no effect.
  • CLOUDFLARE_API_TOKEN. The variable is CLOUDFLARE_TOKEN.
  • LOG_LEVEL. The variable is CERTMATE_LOG_LEVEL.
  • HOST and FLASK_DEBUG. The bind address is not configurable: the container always listens on 0.0.0.0 inside its own network namespace.

A DNS credential configured in the UI is stored in settings.json. To keep it out of that file, a credential field can name its source instead, with api_token_file (a path) or api_token_env (a variable name). The value is read when certbot runs and is not written back.

Ports and Reverse Proxy

Because the bind address inside the container is fixed, restrict exposure when you publish the port: -p 127.0.0.1:8000:8000 makes CertMate reachable on the host's loopback only. For external access, put a reverse proxy with TLS in front of it.

When a proxy is in front, set BEHIND_PROXY=true. CertMate then trusts X-Forwarded-* headers from one proxy hop, so rate limiting and audit entries see the client address rather than the proxy's. Leave it unset when there is no proxy: with it on, a client can forge its own address, which is what the login rate limit is keyed on. When TLS terminates at the proxy, also consider PREFERRED_URL_SCHEME=https, which marks the session cookie Secure.

The compose file includes an optional nginx service in the nginx profile. Create its configuration before starting it; if nginx.conf does not exist on the host, Docker creates an empty directory in its place and nginx fails to start.

cp nginx.conf.example nginx.conf
# replace every <your-domain> in ssl_certificate / ssl_certificate_key
docker compose --profile nginx up -d

Volumes

All persistent state lives in four directories:

  • /app/data: settings.json, admin users, the generated .secret_key, the audit signing key and the scheduler database.
  • /app/certificates: issued certificates and keys.
  • /app/logs: application and audit logs.
  • /app/backups: backup archives.

The image makes these directories owned by group 0, group-writable and setgid, so a process running as any UID in group 0 (rootless podman, OpenShift) can write to them. Secret files are created with mode 0600.

Named volumes inherit these permissions and need no preparation. Bind mounts keep the host directory's ownership; Docker creates missing directories owned by root, which the non-root process cannot write to. Prepare them with the chgrp -R 0 and chmod -R g+rwX commands shown above, or with podman add :U to each mount. If a directory is not writable, CertMate refuses to start with the message "Required directories are not writable by the CertMate process".

To keep certificates somewhere other than /app/certificates, set CERTMATE_CERT_DIR and mount that path. Since v2.35.0 the local storage backend follows it too, unless certificate_storage.cert_dir in the settings names a directory of its own, in which case that directory wins.

Backups

Set CERTMATE_BACKUP_PASSPHRASE if you want automatic backups you can restore from. With it, backups are complete and encrypted at rest (.zip.enc, PBKDF2-SHA256 and Fernet). Without it, automatic backups have their credentials masked: the backup list marks them can_restore: false, and the restore API refuses them on an instance that already holds certificates. The passphrase is read from the environment and never stored in settings.json, and the same passphrase is required to restore. Archives on the host are pruned after 30 days and a lost volume takes them with it, so keep a copy off the host.

Upgrading

State lives in the volumes, not in the image, so upgrading means pulling a newer image and recreating the container with the same mounts. Take a backup first (Settings, Backup, or the API). Settings-format migrations run automatically on boot.

# Docker Compose, with the image: line in use
docker compose pull
docker compose up -d

# docker run
docker pull fabriziosalmi/certmate:latest
docker rm -f certmate
# re-run the original docker run command with the same -v mounts

Before upgrading to v2.35.0

  • A certificate requested from a CA that is not configured on the instance is refused with HTTP 400, naming the CA. Let's Encrypt, and its staging entry, still work with nothing saved. Configure the CA you request, or request one that is configured.
  • If you set CERTMATE_CERT_DIR and the settings do not name a certificate_storage.cert_dir of their own, the storage layer now writes to CERTMATE_CERT_DIR as well.
  • An ACME directory URL configured on a CA account must use https. A plain http URL is refused.

A build refuses to read a settings.json or metadata.json written by a newer version. CERTMATE_ALLOW_SCHEMA_DOWNGRADE=1 overrides this, at the cost of dropping the fields the older build does not understand.

Health Checks

  • /health is the liveness endpoint. It returns 200 whenever the app is serving requests; its JSON status field is healthy or degraded, with per-component checks. The image's HEALTHCHECK calls it with curl every 30 seconds, with a 40-second start period, the same as docker-compose.yml.
  • /health/ready returns 503 when the renewal scheduler is not running or the certbot probe ran and failed. Use it for readiness probes and deploy gates: in either case the instance is up but would renew nothing.

Logs

The container logs to stdout, as JSON by default (CERTMATE_LOG_JSON=false for plain lines), so docker logs certmate or docker compose logs -f certmate shows them. To also write a rotated file on the volume, set CERTMATE_LOG_FILE=/app/logs/certmate.log; the web UI's log stream reads that file.

Recovering Admin Access

If you have lost the admin password:

docker exec -it certmate python scripts/reset_admin_password.py

Building the Image

docker build -t certmate:latest .
