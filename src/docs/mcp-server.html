MCP Server

How to connect an AI assistant to CertMate through the MCP server, which tools it exposes, and how its actions are authorized and audited.

What It Is

The CertMate repository ships a Model Context Protocol (MCP) server in its mcp/ directory. It is a Node.js process that speaks MCP over stdio to an AI assistant and turns each tool call into a request to the CertMate REST API. It holds no state of its own and has no access beyond what the API token you give it allows: every permission check happens in CertMate, not in the MCP server.

Nothing in the server is specific to one assistant. Any MCP client that can start a stdio server works the same way.

Tools

The server exposes the tools below. The minimum role is the one CertMate enforces on the API route the tool calls.

ToolWhat it doesAPI callMinimum role
certmate_list_certificatesLists all certificates with expiry, status and domains.GET /api/certificatesviewer
certmate_get_certificateDetail for one domain: status, days until expiry, SANs, DNS and CA provider, auto-renew flag.GET /api/certificates/<domain>viewer
certmate_get_activityRecent activity and audit entries. Optional limit, 1 to 500, default 100.GET /api/activityviewer
certmate_get_settingsGlobal settings. Secret values are masked.GET /api/settingsviewer
certmate_list_dns_providersDNS providers supported and configured on the instance.GET /api/settings/dns-providersviewer
certmate_diagnosticsA sanitized diagnostic snapshot.GET /api/diagnostics/snapshotadmin
certmate_create_certificateRequests a certificate. domain is required; dns_provider, account_id and ca_provider are optional.POST /api/certificates/createoperator
certmate_renew_certificateForces renewal of an existing certificate.POST /api/certificates/<domain>/renewoperator
certmate_update_certificateReissues a certificate with a new SAN set and/or DNS-01 alias.POST /api/certificates/<domain>/reissueoperator
certmate_get_jobPolls an asynchronous create, renew or update job by job_id.GET /api/certificates/jobs/<job_id>operator
certmate_set_auto_renewEnables or disables automatic renewal for one domain.PUT /api/certificates/<domain>/auto-renewoperator
certmate_download_certificateReturns the certificate, chain, full chain and private key as JSON.GET /api/certificates/<domain>/download?format=jsonoperator
certmate_get_certificate_fileReturns one bundle file as raw PEM text.GET /api/certificates/<domain>/download?file=<file>viewer for cert.pem, chain.pem, fullchain.pem; operator for privkey.pem, combined.pem, cert.pfx

certmate_list_dns_accountsConfigured DNS accounts, credentials masked. Optional provider filter.GET /api/dns/accounts or GET /api/dns/<provider>/accountsadmin
certmate_delete_certificateRemoves the certificate files from disk and the domain from settings.DELETE /api/certificates/<domain>admin

Two of the admin entries are easy to miss. Running deploy hooks and listing DNS accounts both touch stored credentials, so an operator token that can renew certificates still gets a 403 on them. If an operator-scoped agent needs an account id for issuance, put the account_id in its prompt rather than asking it to look one up.

Installation

The server needs Node.js 20 or later (engines.node is >=20.0.0 in mcp/package.json) and npm. From a checkout of the CertMate repository:

cd mcp
npm install

The entry point is mcp/index.js. On start it writes CertMate MCP server running on stdio to stderr.

Configuration

The server reads four environment variables:

  • CERTMATE_URL: the base URL of your CertMate instance. Default http://localhost:8000. A trailing slash is removed. When CertMate runs on another host, use an https:// URL, because the token is sent with every request.
  • CERTMATE_TOKEN: the API bearer token. Required. Without it, every tool call returns Error: CERTMATE_TOKEN environment variable is not defined.
  • CERTMATE_AGENT_SESSION: optional. The session id sent on every call in the X-CertMate-Agent-Session header. If unset, a new UUID is generated each time the process starts. Set it to correlate a run with an external orchestrator's id.
  • CERTMATE_AGENT_ID: optional. A label for this deployment, sent as X-CertMate-Agent-Id. Default certmate-mcp-server.

For Claude Desktop, add the server to claude_desktop_config.json (on macOS under ~/Library/Application Support/Claude/, on Windows under %APPDATA%\Claude\):

{
  "mcpServers": {
    "certmate": {
      "command": "node",
      "args": ["/absolute/path/to/certmate/mcp/index.js"],
      "env": {
        "CERTMATE_URL": "http://localhost:8000",
        "CERTMATE_TOKEN": "your_secure_bearer_token"
      }
    }
  }
}

For any other MCP client, configure it to run node /absolute/path/to/certmate/mcp/index.js with the same environment variables.

Authentication and Roles

The server sends CERTMATE_TOKEN as Authorization: Bearer <token> on every request. CertMate authenticates it and applies the role and domain scope of the key, so the agent can do exactly what the key can do and nothing more. Revoking the key cuts the agent off.

Create a dedicated key for the agent in Settings, on the API Keys tab, or with POST /api/keys (admin only), and give it the lowest role that covers the tools it needs:

  • viewer for an agent that only reads inventory, activity and settings.
  • operator for an agent that creates, renews, reissues or downloads certificates.
  • admin only if it must run deploy hooks, list DNS accounts, read diagnostics or delete certificates.

A viewer or operator key can be limited to specific domains with allowed_domains. A domain-scoped key cannot read, change or poll jobs for domains outside its scope. Admin keys cannot be domain-scoped: CertMate rejects the request with Admin keys cannot be domain-scoped; use the operator role for scoped access. A key can never be created with a higher role than the key or user creating it.

What an Agent Can and Cannot Change

  • Create, renew and update run asynchronously. The server always sends async: true, and CertMate answers with HTTP 202, a job_id and status: "queued". Poll with certmate_get_job; the job moves through queued and running and ends as succeeded or failed. If the issuance queue is full, CertMate returns 429 with the code ISSUANCE_QUEUE_FULL.
  • Since v2.35.0, a ca_provider that is not configured on the instance is refused, not substituted: the create job ends as failed with an error that names the CA, and no certificate is issued from another CA. Let's Encrypt and Let's Encrypt staging need no saved configuration. A failed create job does not emit certificate_failed, so the agent's own report is the signal.
  • certmate_update_certificate cannot change the primary domain; it is the certificate's identity. Omit sans to keep the current SAN set, pass an empty array to drop all SANs, and pass domain_alias: "" to clear the alias.
  • certmate_set_auto_renew requires a real boolean. If the model sends the string "false", the server refuses the call with enabled must be true or false instead of forwarding it.
  • certmate_deploy_certificate runs every enabled deploy hook for the domain with CERTMATE_EVENT=manual; the hooks' event filters are ignored.
  • certmate_delete_certificate is destructive and cannot be undone. It does not revoke the certificate at the CA. It refuses while a create or renew holds the domain lock.
  • No tool writes settings, manages API keys or users, or adds, edits or removes DNS accounts. certmate_get_settings and certmate_list_dns_accounts are read-only and return masked secrets.
  • certmate_download_certificate and certmate_get_certificate_file with privkey.pem, combined.pem or cert.pfx put private key material into the assistant's context. Give the agent an operator key only if that is intended.

Audit Attribution

To tell an agent's actions apart from a person's, give the MCP server its own key with the AI agent key box ticked when you create it (or "is_agent": true in the POST /api/keys body), and use that key as CERTMATE_TOKEN.

CertMate records who acted in an actor block on each audit entry, and it decides the actor's kind from the authenticated key only:

  • A key flagged as an agent key is recorded as actor.kind="agent" with the key's id, and the trigger cause is agent.
  • Any other API key, and the legacy global bearer token, is recorded as api_token. The legacy token also carries no key id and appears as api_user.

The X-CertMate-Agent-Session and X-CertMate-Agent-Id headers are stored as actor.agent_session and actor.agent_id, truncated to 128 characters. They are unauthenticated claims: they let you group one run's actions, but they never turn a non-agent caller into agent. The certmate_get_activity tool reads the same log. See Compliance for the audit chain these entries belong to.

Running an Agent on a Schedule

An assistant that can run a saved prompt on a schedule and call MCP tools can keep certificates renewed on a policy you write in the prompt. The loop:

  1. Call certmate_list_certificates, or certmate_get_certificate per domain, and read days_left.
  2. For each domain that meets your condition, for example days_left < 14, call certmate_renew_certificate.
  3. Poll certmate_get_job with the returned job_id until the status is succeeded or failed.
  4. Report failures. A failed renewal job, other than one refused because the domain was busy, also emits CertMate's certificate_failed event, so configured notifications fire regardless of what the agent does.

This loop needs an operator key.
