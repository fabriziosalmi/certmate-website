Webhooks

How CertMate sends certificate events to an HTTP endpoint: events, request body, templates, authentication, signatures, retries and the API.

What a Generic Webhook Is

A webhook is a notification channel: on a certificate event, CertMate sends an HTTP request to a URL you configure. Slack, Discord, Telegram, ntfy and Gotify each have their own channel type with a fixed request format. The generic type is for any other receiver, and it is the only type that supports a payload template, a method, authentication settings, custom headers and an HMAC signature.

Two switches must be on before anything is sent: Enable Notifications at the top of Settings → Notifications, and the checkbox next to the webhook's name.

Adding a Webhook in the UI

  1. Open Settings → Notifications, turn on Enable Notifications, and expand Webhooks.
  2. Click Add webhook. A new entry starts enabled, with type Generic, method POST, authentication None, no events selected and an empty payload template.
  3. Give it a name and enter the URL. The name identifies the webhook in the delivery log and in save errors.
  4. Use Preview to see the request without sending it, and Test to send one.
  5. Click Save Notification Settings.

Events

Events and their titles:

  • certificate_created: Certificate Created. An adopted certificate uses the same event with the title Certificate Adopted.
  • certificate_renewed: Certificate Renewed
  • certificate_failed: Certificate Failed
  • certificate_revoked: Certificate Revoked
  • certificate_deployed: Certificate Deployed
  • certificate_expiring: Certificate Expiring
  • domain_expiring: Domain Registration Expiring
  • deploy_hook_failed: Deploy Hook Failed
  • certificate_deploy_incomplete: Certificate Not Deployed

The message is <title>: <domain>. CertMate appends (hook: <name>) when the event names a deploy hook, the days left or "expired" for the two expiry events, and — <error> when the event carries an error.

Filtering

There are two filters, and an event must pass both. Notify on Events at the top of the page applies to every channel; Events (leave empty for all) on each webhook applies to that webhook. An empty list means all events.

The UI offers six events to filter on: created, renewed, expiring, revoked, failed and domain expiring. deploy_hook_failed and certificate_deploy_incomplete are delivered whatever either filter says, so a filter cannot silence a failed deployment. certificate_deployed has no checkbox, so a non-empty filter set in the UI drops it; to receive it with a filter in place, add it to the events list through the API.

Expiry warnings

  • certificate_expiring is sent when a certificate reaches 14, 7, 3 or 1 days left, or has expired. With auto-renew off for that certificate, the first warning comes at the renewal threshold instead, if that is later than 14 days.
  • domain_expiring is sent when a tracked domain registration reaches 60, 30, 14, 7 or 1 days left, or has expired.

Each threshold is announced once per expiry date. A renewed certificate has a new expiry date and starts again from the first threshold. Both events carry days_left, days_until_expiry, expires_at, expired and threshold_days in details; certificate_expiring adds auto_renew, and domain_expiring adds registrar and source.

The Default Request

With no payload template, a generic webhook sends this JSON body, with Content-Type: application/json and User-Agent: CertMate-Webhook/2.0:

{
  "event": "certificate_renewed",
  "title": "Certificate Renewed",
  "message": "Certificate Renewed: shop.example.com",
  "details": {"domain": "shop.example.com"},
  "timestamp": "2026-08-21T07:00:00Z"
}

details is the event's own data, so its fields depend on the event: for example hook_name, exit_code and error on deploy_hook_failed, or failed and total on certificate_deploy_incomplete. timestamp is UTC.

Payload Templates

A payload template is JSON text with {{placeholders}}, rendered for each event. It replaces the default body.

{"text": "{{title}}: {{domain}} ({{event}})", "days_left": {{details.days_until_expiry}}}
  • {{event}}: the event name
  • {{title}}: the title, for example Certificate Renewed
  • {{message}}: the one-line message
  • {{timestamp}}: ISO-8601 UTC
  • {{domain}}: shortcut for details.domain
  • {{details}}: the whole event data as a JSON object
  • {{details.<field>}}: one field of it, such as details.error or details.expires_at

A placeholder inside a JSON string is inserted as an escaped string fragment, so quotes, newlines or backslashes in a value cannot break out of the string. A placeholder outside a string is inserted as a JSON literal: a number, boolean, object or quoted string. An unknown placeholder becomes an empty fragment inside a string and null outside one.

The template is checked when you save, by rendering it for a sample certificate_renewed event. If the result is not valid JSON, the save fails with HTTP 400 and a message of the form webhook <name>: payload_template does not render to valid JSON: ....

Preview and Test

Preview renders the request for a sample event without sending it and shows the method, URL, headers and body. Header values whose names contain authorization, key, token, secret or cookie are shown as ********, and the signature appears as a placeholder. Preview works for generic webhooks only.

Test sends one real request for the event test using the settings in the form, saved or not. It makes a single attempt and does not write to the delivery log.

Method, Authentication, Timeout and Attempts

  • Method: POST (default), PUT or PATCH.
  • Authentication: None (default); Bearer token, sent as Authorization: Bearer <token>; Basic, with a username and password; or Header, a header name (default X-API-Key, letters, digits and hyphens only) and its value.
  • Timeout: 1 to 60 seconds, default 10.
  • Attempts: total deliveries, 1 to 5, default 3. The API also accepts 0, which is treated as 1.

Custom Headers are added to every request. The authentication header is applied after them, so it replaces a custom header of the same name. Saving a Bearer or Header webhook without a token, or a Basic webhook without both username and password, fails with a message naming the missing field.

Retries

After a failed attempt CertMate waits 1 second, then 2, then 4, doubling each time, until the attempts are used up. It does not retry when a retry cannot change the result:

  • configuration errors, such as a missing URL, a non-HTTP scheme, a blocked internal target or a template that does not render;
  • HTTP 4xx responses, except 408, 425 and 429.

5xx responses and connection errors are retried.

Signature

When a generic webhook has an HMAC secret, every request carries:

X-CertMate-Signature: t=<unix-timestamp>,v1=<hex>

v1 is the hex HMAC-SHA256 of <t>. followed by the request body, keyed with the secret. Compute it over the exact raw body you received, which is the rendered template if you use one. Reject old timestamps to stop replays. In Python, with body as bytes:

import hmac, hashlib, time

def verify(secret, header, body, max_age=300):
    parts = dict(p.split('=', 1) for p in header.split(','))
    if abs(time.time() - int(parts['t'])) > max_age:
        return False
    expected = hmac.new(secret.encode(), f"{parts['t']}.".encode() + body,
                        hashlib.sha256).hexdigest()
    return hmac.compare_digest(expected, parts['v1'])

Outbound Restrictions

The URL must start with http:// or https://. CertMate resolves the host and refuses the request if any resolved address is private, loopback, link-local, reserved, multicast or unspecified. The error is: "Webhook target resolves to an internal/loopback address; refused (SSRF guard). Set CERTMATE_ALLOW_INTERNAL_WEBHOOKS=true to permit internal targets." A host that does not resolve is not treated as internal.

If your receiver is on an internal network, set CERTMATE_ALLOW_INTERNAL_WEBHOOKS to true, 1 or yes in CertMate's environment.

Redirects are followed, and each redirect target is checked the same way. When a redirect changes scheme, host or port, CertMate removes the Authorization, Proxy-Authorization and X-CertMate-Signature headers before following it. Other headers, including a Header-type authentication header, are not removed.

Stored Credentials

When the configuration is read back, credential fields are returned as ********: fields whose names contain token, secret, password, key, credential, hmac or authorization, the webhook URL, and every custom header value. Saving a form that still holds ******** keeps the stored value.

Delivery Log

Each delivery, after its retries, is appended to webhook_deliveries.jsonl in CertMate's data directory, which keeps the most recent 1,000 entries. An entry records the time, webhook name and type, event, URL, HTTP status, success, number of attempts, error and duration in milliseconds. Email deliveries are logged in the same file.

In the UI, Recent Deliveries below the webhook list shows the latest 50 entries.

API

All of these endpoints require the admin role.

  • GET /api/notifications/config returns the notifications block, with credentials masked. Webhooks are under channels.webhooks.
  • POST /api/notifications/config saves it. The body is merged into the stored block, and the webhooks list replaces the stored list, with masked values restored from it. The response on success is {"message": "Notification settings saved"}.
  • POST /api/notifications/test with {"channel_type": "webhook", "config": {...}} sends a test request through one webhook without saving it, and returns success with the status or the error.
  • POST /api/notifications/webhook/preview with {"config": {...}, "event": "certificate_renewed"} renders the request without sending it. event defaults to certificate_renewed and must be lowercase letters and underscores. An invalid configuration or template returns 400 with the reason.
  • GET /api/webhooks/deliveries?limit=50 returns recent deliveries, newest first. limit defaults to 50 and is clamped to 1–500.

A generic webhook entry uses these fields:

{
  "enabled": true,
  "name": "itsm",
  "type": "generic",
  "url": "https://itsm.example.com/hooks/certmate",
  "secret": "",
  "events": [],
  "headers": {},
  "method": "POST",
  "auth_type": "bearer",
  "auth_token": "...",
  "auth_username": "",
  "auth_password": "",
  "auth_header": "",
  "timeout": 10,
  "max_retries": 3,
  "payload_template": ""
}
