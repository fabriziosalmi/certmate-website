Contributing to CertMate

How to set up a development checkout, run the tests, and get a pull request through the gates CertMate enforces.

Contributions are welcome as pull requests to fabriziosalmi/certmate. Most of what a pull request has to satisfy is automated: the commands on this page are the ones CI runs, so running them locally is faster than waiting for the PR to fail.

How to contribute

  1. Fork the repository.
  2. Create a feature branch: git checkout -b feature/my-change.
  3. Commit your changes.
  4. Push the branch.
  5. Open a pull request.

Development setup

git clone https://github.com/fabriziosalmi/certmate.git
cd certmate
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
pip install -r requirements-test.txt
python app.py

requirements-test.txt installs pytest and Playwright, plus clients/certmate-sdk and clients/certmate-cli in editable mode (the CLI depends on the SDK), so the end-to-end tests exercise the real clients against the server.

The linters are not in requirements-test.txt. CI pins them, and so should you:

pip install flake8==7.3.0 bandit==1.9.4

Running the tests

./run-tests.sh
# or, equivalently:
pytest -v --tb=short -m "not ui and not e2e"

Keep the marker expression. A bare pytest runs the Playwright ui suite in the same process as everything else and reports failures unrelated to your change, and the e2e tests need a running instance. make test uses the same selection.

The UI suite runs on its own and needs Docker:

pytest -m ui

The e2e fixtures build the Docker image and manage a container for the session. Without Docker, point the suite at an instance you started yourself:

# Terminal 1
gunicorn --bind 127.0.0.1:18888 --workers 1 --threads 8 --timeout 300 app:app

# Terminal 2
CERTMATE_E2E_BASE_URL=http://localhost:18888 pytest -m "e2e and not ui"

That instance must start from a clean data directory, because the e2e tests assume first-boot state. The real-issuance tests also need CLOUDFLARE_API_TOKEN and a CERTMATE_TEST_DOMAIN you control; they issue real Let's Encrypt certificates and skip when the token is absent.

Gates a pull request must pass

GateCommand
Syntax and bug-class lint (fails CI)flake8 . --count --select=E9,F63,F7,F82,F811,F632,E711,E712,E713,E714,F401,F841,E722 --show-source
Complexity budget (fails CI)python scripts/check_complexity_budget.py
Security scan (fails CI)bandit -r modules/ app.py --severity-level medium
Tests, with a 75% coverage floor on modules/pytest -m "not ui and not network" --cov=modules --cov-fail-under=75
Theme tokenspython3 scripts/theme_codemod.py --check
CSS bundle freshnessnpm ci && npm run css:build, then commit static/css/tailwind.min.css
No emoji in release notes (RELEASE_NOTES.md, docs/releases/).github/workflows/lint-emoji.yml
Image buildsdocker build -t certmate:test .
  • The full style pass (flake8 . without --select) is informational: CI runs it with --exit-zero. Do not reformat unrelated files to quieten it.
  • The coverage floor is a ratchet. Raise it; never lower it to make a red build pass.
  • Every function may reach a cyclomatic complexity of 40. The functions already above that are listed in scripts/check_complexity_budget.py with their current value, and the check fails if a new function exceeds the limit without an entry, if a budgeted function gets worse, if one gets better without its entry coming down, or if an entry matches nothing. Prefer decomposing a function to adding an entry.

Editing templates or CSS

Rebuild the CSS bundle and commit it: CI fails if the committed static/css/tailwind.min.css differs from a fresh build. Use the semantic theme tokens instead of raw *-600 dark:*-400 colour pairs; theme_codemod.py --check enforces this.

Editing docs

tests/test_docs_navigation.py fails if a page is no longer linked from its index.md, if an index points at a missing file, or if the README's documentation table drops a page. Translations live one directory below the English originals, so a relative link out of docs/<lang>/ needs ../../, not ../.

Getting a pull request merged

Branch protection applies to everyone, admins included:

  • Every review conversation must be resolved, including those opened by Copilot and CodeQL. Read them before resolving them.
  • CI must be green. Auto-merge is disabled, so a maintainer merges by hand.

.github/required-checks.yml lists every job that runs on a pull request as gating (the PR cannot merge without it) or advisory (it reports, with the reason it does not block written next to it). tests/test_required_checks_registry.py fails if a job is missing from that file. Read the advisory results too, for example storage-live and acme-dns-live, which boot real service containers.

The ui job runs only when a PR touches the frontend, as decided by scripts/ui_paths_changed.py; the required check is ui-gate, which always runs and treats a skipped ui job as a pass. If you add a frontend directory, add it to that script's PATTERNS.

If your change touches certificate issuance, a DNS provider or the ACME path, say so in the PR. scripts/release.sh detects those paths and requires a real certificate issued against Let's Encrypt staging before a release containing the change can be cut.

Do not add version strings by hand. scripts/release.sh bumps every user-facing copy and tests/test_version_consistency.py pins them; a new place that shows the version must be added to both.

Code style

  • Match the conventions of the file you are editing.
  • Comments explain why, especially where the obvious implementation is wrong.
  • Use the present tense for what the code does, and the past tense (or a leading Previously:) for what it used to do wrongly, so a comment about a fixed defect is not read as current behaviour.
  • Add tests for new behaviour. For a bug fix, check that the test fails against the old code.
# WRONG: reads as the current behaviour
# The settings entry is written after the lock is released, so a renewal
# can interleave and read the old provider.

# RIGHT: the tense says which is which
# Both writes happen under one lock. Previously the settings entry was
# written after the lock was released, so a renewal could interleave and
# read the old provider.

Reporting issues

Open an issue on the issue tracker with:

  • steps to reproduce;
  • expected and actual behaviour;
  • the CertMate version (GET /health, or certmate --version for the CLI) and the environment: Docker tag, DNS provider, CA.

Questions and ideas go to GitHub Discussions. Security issues do not go on the public tracker; follow the security policy.
