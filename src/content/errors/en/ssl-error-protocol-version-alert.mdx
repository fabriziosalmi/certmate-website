## What it means

Firefox reports `SSL_ERROR_PROTOCOL_VERSION_ALERT` with the message *"Peer
reports incompatible or unsupported protocol version."* The error page adds:
*"This website might not support the TLS 1.2 protocol, which is the minimum
version supported by Firefox."*

The word that matters is *reports*. Firefox sent its ClientHello, and the
server replied with a TLS alert whose description is `protocol_version`: it
found no version in Firefox's offer that it was willing to use, and closed the
connection. Firefox raises this error when it receives that alert. The refusal
is the server's.

That is the difference from `SSL_ERROR_UNSUPPORTED_VERSION`, where the server
picks a version and Firefox refuses it. It also differs from
`SSL_ERROR_NO_CYPHER_OVERLAP`, where the disagreement is over cipher suites.

## Common causes

- **Firefox's maximum was lowered.** With `security.tls.version.max` set to
  `3` (TLS 1.2) in `about:config`, or by the `SSLVersionMax` enterprise
  policy, Firefox no longer offers TLS 1.3. A server configured for TLS 1.3
  only has nothing to agree to. The default maximum is `4`, TLS 1.3. If one
  browser fails and others do not, this is the first thing to check.
- **An old server that refuses rather than negotiates down.** A server whose
  highest version is TLS 1.0 or 1.1 should answer with that version, which
  produces `SSL_ERROR_UNSUPPORTED_VERSION` instead. Some implementations
  answer an offer of a newer version with the alert. Firefox's own
  connection code lists this alert among the signs of a server that cannot
  handle newer TLS versions.
- **A device in front of the server.** A load balancer, proxy or inspecting
  firewall that terminates TLS answers with its own version policy, not the
  server's.

Firefox does not retry at a lower version by default:
`security.tls.version.fallback-limit` defaults to `4`, which leaves nothing
lower to fall back to.

## How to fix it

**1. Ask the server which versions it will complete a handshake with:**

```bash
for v in tls1 tls1_1 tls1_2 tls1_3; do
  printf '%-9s ' "$v"
  echo | openssl s_client -connect example.com:443 -servername example.com -"$v" 2>&1 \
    | grep -q 'Cipher is [A-Z]' && echo accepted || echo refused
done
```

- Only `tls1_3` accepted: the server is TLS 1.3-only, and the browser that
  fails is almost certainly not offering TLS 1.3. Go to step 2.
- Neither `tls1_2` nor `tls1_3` accepted: the server, or the device in front of
  it, is the cause. Go to step 3.

Many current OpenSSL builds will not offer TLS 1.0 or 1.1 at all, so `refused`
next to those two can mean your own machine declined to ask.

**2. Check the browser.** Open `about:config` and search for
`security.tls.version`. A modified `security.tls.version.max` below `4` is the
cause. When any `security.tls.version.*`, `security.ssl3.*` or
`security.tls13.*` preference has a changed value, the error page offers
**Restore default settings**. A value set by enterprise policy is locked and
has to be changed in the policy. The page shows the same "might not support
TLS 1.2" notice in this case too, even though the server is not the problem.

**3. Fix the server.** Enable TLS 1.2 and 1.3. On nginx:

```nginx
ssl_protocols TLSv1.2 TLSv1.3;
```

On a managed load balancer or CDN, select a current TLS policy. If a
TLS-terminating device sits in front of the server, it is the configuration
that answers the browser, and the one to change.

## Prevent it from recurring

When the cause is a browser preference, nothing on the server side can see it,
CertMate included.

When the cause is the server, it is the same condition as
`SSL_ERROR_UNSUPPORTED_VERSION`: a host that cannot do TLS 1.2. CertMate's
probes require TLS 1.2, so such a host shows in the inventory as `unreachable`
with a `tls_error`. The opt-in `weak_tls` check, available since v2.34.0,
goes further and reports a host as `failing` while it still accepts TLS 1.0
or 1.1 next to newer versions. It is off by default; see
[Domain health](/docs/domain-health.html) for how to turn it on.

## Related errors

- `SSL_ERROR_UNSUPPORTED_VERSION`: the server chose a version and Firefox refused it.
- `SSL_ERROR_NO_CYPHER_OVERLAP`: no cipher suite in common.
- `ERR_SSL_VERSION_OR_CIPHER_MISMATCH`: the Chromium code for version and cipher mismatches.
- `ERR_SSL_PROTOCOL_ERROR`: a broader Chromium handshake failure.
