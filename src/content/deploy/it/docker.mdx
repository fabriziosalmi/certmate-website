## Il principio: tieni i certificati fuori dall'immagine

Non includere mai certificati o chiavi private in un'immagine Docker — ruotano
molto più spesso del codice, e una chiave in un layer è una chiave nel tuo
registry. Montali invece a runtime e termina il TLS sull'edge.

## Opzione A — termina il TLS su un reverse proxy

Metti un reverse proxy che termina il TLS (Nginx, Caddy, Traefik) davanti al
container dell'app e monta il certificato nel proxy:

```yaml
# docker-compose.yml
services:
  proxy:
    image: nginx:stable
    ports:
      - "443:443"
      - "80:80"
    volumes:
      - ./nginx.conf:/etc/nginx/conf.d/default.conf:ro
      - /etc/letsencrypt/live/example.com:/certs:ro   # fullchain.pem + privkey.pem
    restart: unless-stopped
  app:
    image: your/app:latest
    expose:
      - "8080"
```

La config del proxy punta a `/certs/fullchain.pem` e `/certs/privkey.pem`. Il
container dell'app non vede mai la chiave.

## Opzione B — monta i certificati direttamente nell'app

Se l'app termina il TLS da sé, monta la cartella in sola lettura:

```bash
docker run -d \
  -v /etc/letsencrypt/live/example.com:/certs:ro \
  -e TLS_CERT=/certs/fullchain.pem \
  -e TLS_KEY=/certs/privkey.pem \
  -p 443:8443 your/app:latest
```

## Rinnovo: ricarica il container, non ricostruirlo

Quando il certificato si rinnova sull'host, i file montati si aggiornano — ma un
proxy a lunga esecuzione può tenere ancora in memoria il vecchio certificato.
Ricarica (non ricostruire) il container:

```bash
certbot renew --deploy-hook "docker exec proxy nginx -s reload"
```

## Verifica

```bash
echo | openssl s_client -connect example.com:443 -servername example.com 2>/dev/null \
  | openssl x509 -noout -dates
```

## Il modo senza pensieri

Puoi eseguire CertMate stesso come container (`docker run` / compose) per
emettere e rinnovare certificati su ogni provider DNS supportato — nessuna
chiave nelle immagini, gestito da UI o API REST. I suoi deploy hook girano
dentro il container di CertMate, che contiene `sh`, `bash`, `curl` e `openssl`
e non la CLI `docker`, quindi un hook non può fare `docker exec` nel proxy. Per
ricaricare il proxy nel momento in cui un certificato ruota, fai chiamare
all'hook qualcosa che possa farlo via rete, oppure costruisci una tua immagine
su quella di CertMate con gli strumenti che servono all'hook.
