## Prerequisiti

- Un dominio il cui record DNS A/AAAA punta al server.
- Nginx installato, in ascolto sulla porta 80 (serve per la validazione HTTP-01) e 443.
- Accesso root/sudo.

## 1. Emetti il certificato

Per un sito pubblico, HTTP-01 via certbot è la via più semplice:

```bash
sudo certbot certonly --webroot -w /var/www/html \
  -d example.com -d www.example.com
```

Per i wildcard (`*.example.com`) serve invece DNS-01 — CertMate gestisce DNS-01
su ogni provider supportato senza dover gestire un plugin diverso per ogni host.

Certbot scrive i file in `/etc/letsencrypt/live/example.com/`.

## 2. Punta Nginx alla catena completa

L'errore TLS più comune con Nginx è servire `cert.pem` (solo foglia), che
provoca `NET::ERR_CERT_AUTHORITY_INVALID` per alcuni client. Usa sempre
`fullchain.pem`:

```nginx
server {
    listen 443 ssl;
    listen [::]:443 ssl;
    http2 on;
    server_name example.com www.example.com;

    ssl_certificate     /etc/letsencrypt/live/example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/example.com/privkey.pem;

    ssl_protocols       TLSv1.2 TLSv1.3;
    ssl_ciphers         HIGH:!aNULL:!MD5;
    ssl_prefer_server_ciphers off;
}

server {
    listen 80;
    server_name example.com www.example.com;
    return 301 https://$host$request_uri;
}
```

Verifica e ricarica:

```bash
sudo nginx -t && sudo systemctl reload nginx
```

## 3. Verifica

```bash
echo | openssl s_client -connect example.com:443 -servername example.com 2>/dev/null \
  | openssl x509 -noout -issuer -dates
```

Dovresti vedere l'issuer della CA e un `notAfter` recente.

## 4. Rinnovo automatico (con reload reale)

Un rinnovo che non ricarica Nginx lascia il vecchio certificato in memoria. Con
certbot, aggiungi un deploy hook:

```bash
sudo certbot renew --deploy-hook "systemctl reload nginx"
```

## Il modo senza pensieri

CertMate emette e rinnova il certificato (HTTP-01 o DNS-01 su ogni provider supportato), poi
esegue un deploy hook per distribuire `fullchain.pem` + `privkey.pem` a questo
host e ricaricare Nginx — così il certificato servito è sempre aggiornato e la
catena non resta mai a metà. Lo gestisci da UI o API REST invece che con cron
host per host.
